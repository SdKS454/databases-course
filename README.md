**HW7:** [порядок показа](HW7/README.md#showcase) · [отчёт с SQL и фотографиями](HW7/transaction.md#contents)

## Описание проекта

Проект посвящён проектированию базы данных для киберспортивной дисциплины **Dota 2**. Предметная область охватывает профессиональные матчи, игроков и команды, героев, предметы, а также индивидуальную статистику выступлений: киллы, смерти, ассисты, заработанное золото и опыт.

База решает проблему разрозненности данных о матчах: вместо того чтобы хранить информацию о каждой игре в отдельных таблицах или текстовых логах, единая схема позволяет в удобном виде хранить историю матчей, связывать их с игроками и героями, а затем анализировать результаты — например, находить сильнейших игроков на конкретном герое или команды с лучшей статистикой в турнирах.

## Содержимое домашних работ

### HW1 — Проектирование базы данных
- **Сущности**: Players, Teams, Matches, Heroes, Items, PlayerMatchStats, PlayerMatchItems
- **ER-диаграмма** в нотации Crow's Foot (см. `HW1/ER_diagram.png`)
- **SQL-схема** для PostgreSQL (см. `HW1/README.md`)
- **2 запроса на реляционной алгебре**: с операциями σ и π; с операцией соединения ⋈

### HW2 — Работа с таблицами в PostgreSQL
- **CREATE TABLE** — 7 таблиц по ER-диаграмме
- **ALTER TABLE** — 5 запросов изменения структуры
- **INSERT** — 4–5 тестовых записей в каждую таблицу
- **UPDATE** — 5 запросов изменения данных
- **Скриншоты** структуры — текстовый вывод psql в `HW2/output/`

### HW3 — Нормализация до 3НФ и НФБК
- **Разбор функциональных зависимостей** для всех 7 таблиц HW2
- **Найденные аномалии**: составной атрибут `Heroes.role` (1НФ), повторяющаяся группа сторон в `Matches`, транзитивная зависимость `Players.rank ← Players.mmr` (3НФ), дубль справочника регионов, неверный ключ в `PlayerMatchItems`
- **Решения**: `HeroRoles`, `MatchTeams`, справочник `Ranks`, справочник `Regions`, `PlayerInventory`
- **Итог**: 14 таблиц в НФБК, вынесено в схему `nf` (см. `HW3/ER_diagram_nf.png`)
- **Миграция** данных HW2 с блоком проверки целостности
- **4 задачи на нормализацию** для разбора на паре

### HW4 — SELECT, CASE и JOIN
- **SELECT с CASE**: ранг игрока по MMR, категория длительности матча
- **INNER JOIN**: команды и регионы, статистика игроков и герои
- **LEFT / RIGHT / FULL OUTER JOIN**: команды без региона, игроки без команды, сохранение неприкреплённых строк
- **CROSS JOIN**: декартово произведение режимов игры и рангов
- **12 запросов** на схеме `nf` (см. `HW4/select_join_queries.md`)

### HW5 — Агрегатные функции и группировка
- **Агрегатные функции**: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`, `STRING_AGG` — сводка по таблице и склейка состава команд в строку
- **GROUP BY + HAVING**: агрегаты по командам и героям, фильтр готовых групп
- **GROUPING SETS, ROLLUP, CUBE**: итоги по регионам и командам (`ROLLUP`), пересечение «режим игры × атрибут героя» (`CUBE` и тот же набор группировок через `GROUPING SETS`), разметка итогов через `GROUPING()`
- **Полный запрос**: `SELECT`, `FROM`, `WHERE`, `GROUP BY`, `HAVING`, `ORDER BY` в двух задачах
- **9 запросов** с реальными результатами — скриншоты в `HW5/screenshots/`, вывод psql в `HW5/output/`

### HW6 — Подзапросы, CTE и оконные функции

- **Подзапросы:** по 2 примера в `SELECT`, `FROM`, `WHERE`, `HAVING`, с `ALL`, `IN`, `ANY`, `EXISTS` и сравнением нескольких столбцов; ещё 5 коррелированных — **23 запроса**.
- **CTE и операции множеств:** 3 CTE, включая рекурсивный обход связей команд; по одному `UNION`, `INTERSECT`, `EXCEPT`.
- **Оконные функции:** `PARTITION BY`, `ORDER BY`, рамки `ROWS` и `RANGE`, `ROW_NUMBER`, `RANK`, `DENSE_RANK`, `LAG`, `LEAD`, `FIRST_VALUE`, `LAST_VALUE` — вместе с CTE **21 запрос**.
- **Проверка:** все 44 запроса выполнены на PostgreSQL 16.15; результаты приведены в отчётах и `HW6/output/`, изображения локальных результатов — в `HW6/screenshots/`.
- **Порядок запуска:** сначала подзапросы на исходных данных HW2–HW3, затем дополнительные данные и оконные функции; см. [HW6/README.md](HW6/README.md).

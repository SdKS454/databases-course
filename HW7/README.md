# HW7 — запуск опытов с транзакциями в pgAdmin

Основной отчёт по требованию презентации: [transaction.md](transaction.md).
Предметная область — Dota 2, схема `nf` из HW3/HW6.

## Если работаю на другом ПК

Полный план от создания базы до PR: [START_HERE.md](START_HERE.md).
В новой базе сначала выполнить [00_bootstrap_new_pc.sql](00_bootstrap_new_pc.sql),
затем `01_prepare.sql`. Bootstrap создаёт 14 таблиц, два представления и
исходные данные HW3/HW6; старые скрипты HW2/HW3 не нужны.
При существующей схеме nf bootstrap останавливается, а не пересоздаёт её.

## С чего начать

1. Сделать копию учебной базы или использовать существующую базу HW6.
2. Открыть **00_check_schema.sql** и выполнить. Если схема `nf` отсутствует или
   её поля отличаются, прислать результат проверки — не пересоздавать свою базу.
3. Выполнить **01_prepare.sql целиком**. Он использует только отдельные строки
   с зарезервированным префиксом `HW7_TX_` в обычных таблицах `nf`.
4. Открыть два Query Tool **одной и той же базы**. В обоих выполнить
   `SELECT current_database(), pg_backend_pid();`: имена базы совпадают,
   идентификаторы соединений различаются.
5. Оставить Auto-commit включённым, Auto-rollback выключенным. Явные BEGIN
   и завершающие команды уже есть в сценариях.
6. Начать с **sql/01_commit_a/T1.sql**. Выполнять выделением по одному шагу.
7. Для сценариев 07–22 открыть соответствующие **T1.sql** и **T2.sql**
   и чередовать шаги по таблице ниже. Номера общие для обоих файлов.
8. Сохранить фотографии результатов. Их ещё нет: протоколы `output` —
   фактический текст локальной проверки, не имитация скриншотов pgAdmin.

**Не запускать файлы T1/T2 целиком.** В ошибочных сценариях следующий ROLLBACK
выполнить отдельным выделением после ожидаемой ошибки.
Если вкладка осталась в состоянии aborted, выполнить в ней `ROLLBACK;`.
Если запрос ждёт блокировку, проверить незавершённые транзакции в обеих вкладках.

## Повтор и очистка

Для полного повторения закончить транзакции в обеих вкладках, затем заново
выполнить `01_prepare.sql`. Он сбрасывает **только строки HW7_TX_**.
При повторном выполнении одного сценария без подготовки начальные данные
могут уже отличаться или INSERT встретит существующее уникальное имя.

После всех опытов `99_cleanup.sql` удаляет только данные этой работы.
Не выполнять очистку или подготовку, пока T1/T2 ещё открыты.

Пока демонстрационные строки не удалены, общие агрегаты HW5/HW6 могут учитывать
их и давать другие числа. После `99_cleanup.sql` исходные наборы строк восстановлены.

Идентификаторы SERIAL могут иметь пропуски после отката. Это нормальное
поведение PostgreSQL: последовательности не откатываются вместе с таблицами.

Схема и исходные данные доступны в репозитории: актуальная БД нужна только
если `00_check_schema.sql` покажет отличия. Все исходные ID ищутся по именам,
чужие таблицы и схема не пересоздаются.

## Что находится в папке

- `transaction.md` — полный отчёт: SQL, фактические результаты и выводы.
- `00_check_schema.sql` — чтение структуры текущей базы.
- `01_prepare.sql` — подготовка отдельного набора строк для опытов.
- `sql/` — 24 сценария, T1.sql и при необходимости T2.sql.
- `99_cleanup.sql` — удаление только собственных строк HW7_TX_.
- `output/` — реальные протоколы локального выполнения и сводка проверки.
- `screenshots/README.md` — какие фотографии сохранить после своего прогона.

Фотографии pgAdmin и обновление корневого README добавляются после ручной
проверки. На этом этапе ничего не закоммичено и не отправлено в GitHub.
